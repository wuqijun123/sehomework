# VP Lab 本地演示版

**虚拟参赛（VP）：**1～3 个账号可以选同一场历史赛，各自计分并保存补题。选场页按成员水平推荐最多三场；实战后台自动同步全部成员，终场生成仅房内可见的固定模板战报。启动和赛库选择见[训练房说明](../README.md)，算法、接口与验证见[ABC 验收说明](../docs/VP房间ABC验收.md)。下文说明个人复盘模块。

面向算法竞赛的训练工作台，当前 v0.3 支持在线获取 CF 提交与源码、提交修改对比、代码旁 AI 复盘、个人经验库、画像、概率估算与补题流程。后端使用 Python 3.10 及以上版本与标准库；前端内置 KaTeX 公式渲染资源，无需在线 CDN。

前端采用 Vben Admin 的 Vue / Ant Design Vue 布局，已包含构建产物。开发与重新构建见 [前端说明](frontend/VPLAB.md)。

## 启动

**智能推荐：**与日常练习独立。根据本次文字偏好进行本地混合检索与 AI 审查，保存一道推荐。基础资料池约 100 题，推荐可扩展到池外；题面内容请求直接搜索全部符合条件的可用题面。独立设置默认使用 CF Rating 上下各 200，无 Rating 时参考 1800，也可手动指定范围和是否包含尝试过的题。只共享 CF 题库、公开资料与提交记录，不读写日常练习的动态 Rating、训练状态、冷却或反馈。每批新增资料卡至少 80% 同时有题解正文与参考代码；推荐本身不受此门槛限制。

点击“准备候选池”整理候选和已有题面；“同步 CF 并整理”更新绑定账号最近最多 1000 次公开提交后整理。“补齐候选题解”在后台获取本题公开题解及其中附带的代码，支持停止；查看资料时需主动展开解法。成功资料跨用户复用，失败保留原因并暂缓 15 分钟。资料准备不调用 AI。填写偏好后可以直接“生成推荐”：理解需求 → 本地检索 → 每批 8 道、最多两批原文审查 → 比较候选题 → 保存结果及符合收录规则的资料卡。每轮最多 9 次 DeepSeek 调用，不发送用户私有提交源码；查看、刷新或复用相同结果不调用模型。智能推荐的开始／跳过／AC 反馈流程尚未接入。原始资料不会因候选移出而删除，候选顺序不是 AI 推荐排名。

HTML 题解获取只使用 Python 标准库；自动解析文字型 PDF 可选安装 `python -m pip install -r requirements-editorials.txt`，未安装时会明确显示依赖缺失。PDF 只匹配本题题号和题名，不把整场题解或其他版本充当本题题解；公式和图片可能需要对照原文件。公开接口不保证始终可用，题面／题解入口访问受限会停止整批；独立提交源码入口受限时保留链接并暂缓该入口。后台任务进度保留在进程内，重启后可重新准备并复用已保存资料。

正文和代码分别补全：取得正文后仍检查本题博客章节的代码块和提交链接；正文尚未加载也不会丢弃已有代码。旧版仅含正文的缓存会升级补全，失败保留原资料。页面区分“代码已缓存”“仅有代码链接”“暂未取得”，找到链接不计入源码成功数。公开提交页只有在题号、提交编号匹配且返回源码时才保存；提交页访问受限时保留链接并暂缓源码请求15分钟，不使用用户账号或绕过验证。附带代码不等同于已核验的完整AC代码，也不会自动执行。

准备层使用 `training_archive.py`、`recommendation_pool.py`，默认读取 `data/vp-ready.zip`，可用 `VPLAB_INTELLIGENT_ARCHIVE` 指定其他兼容快照。基础池按 80% 题解与代码覆盖率准备；推荐不再要求基础池满额，资料不全也可参与审查。每批新增资料卡至少 80% 同时有题解和代码；停止或访问受限时保留资料，下次继续准备。接口见 [智能推荐设计](design/intelligent-recommendation.md)。可用 `python -X utf8 -m unittest discover -s tests -p test_intelligent.py -v` 验证基础规则，`test_pool_quality.py` 验证资料门槛和逐题筛入；可选浏览器验收为 `node tests/intelligent_browser.cjs`，支持 `VP_PLAYWRIGHT_MODULE`、`VP_BROWSER_EXE` 环境变量，使用临时数据库和模拟题库，不触发真实 CF 或模型调用。

智能推荐额外依赖：`python -m pip install -r requirements-recommendation.txt`。本地语义模型为 `intfloat/multilingual-e5-small`，可运行 `python setup_recommendation_model.py` 下载固定版本的 ONNX 与 tokenizer（约 135 MB）；默认保存在 `.local/models/multilingual-e5-small`，也可通过 `VPLAB_EMBEDDING_MODEL` 指定目录。缺模型时会明确报错，不悄悄改为纯关键词检索。模型和向量缓存不入 Git。

DeepSeek 密钥复用“数据与账号”的当前用户配置，或使用服务器环境变量 `DEEPSEEK_API_KEY`；密钥不会写入推荐快照或日志。后台推荐可停止，已发出的请求可能计费，但取消后不会发下一次请求。任务进度与结果入 SQLite；重启后未完成任务标记为中断，学习卡和已有结果保留，不自动继续付费调用。

推荐入口：`http://127.0.0.1:8765/?tab=intelligent`。本轮仅使用明确偏好、独立难度与已同步的完成记录；个人经验库与近期训练画像尚未加入检索，当前不宣称使用这些信息。`python -m unittest discover -s tests -p test_smart_recommendation.py` 可离线验证调用流程、隔离、取消及快照；浏览器验收也使用明确标记的模型替身，不产生费用。

检索按需求选择题面、解法资料或基础信息；明确算法方向先筛标签。新旧题按同一原始证据规则排序，每题每次只取最相关片段，资料卡和缓存身份不再额外增加检索分数。卡片保留给 AI 审查与复用。可运行 `python -m unittest discover -s tests -p "test_smart*.py"` 检查来源路由、排序、工作流与资料卡收录规则。

题面内容请求由 AI 当次生成最多 6 组中英查询、别名及关联概念，直接对全部符合用户条件的可用原文分块检索。BM25 和向量各自读取完整语料，按题融合后最多送审 16 道；不预先给每题生成关键词卡，也不经过 64 题预筛。命中的原文片段带位置回传，长题面后部也能送审。首次本地向量准备较慢，显示进度并逐批缓存；后续请求复用，无远程向量费用。新增或变化的题面会使旧结果过期。

题面检索块至少包含 80 个非空白字符和文字或数字；纯标点不进入索引。过短尾块合并或补足前文，最多 480 token；正文已覆盖后停止分块，避免重复索引末尾句号。完整文本仍过短时不建立题面检索块。分块规则升级后旧推荐结果失效，原始资料保留。

推荐采用“有候选就选出一题供尝试”的策略：普通偏好的程度和侧重点用于排序，部分匹配也能推荐。没有明确匹配时最多审查两批，然后比较所有已送审候选；资料有限或匹配不完整会在结果中注明，不冒充完全符合。只有没有可送审候选或调用失败时才无法给题。当前难度、AC 和明确方向的筛选继续生效。

双击 `StartDemo.cmd`，或在此目录运行 `python server.py --browser`。访问 http://127.0.0.1:8765 。关闭启动终端即可停止服务；端口被占用时使用 `python server.py --port 8766 --browser`。

重复双击启动器时，如果端口上已运行兼容版本的 VP Lab，会直接打开现有页面，启动器正常退出；不会重复启动服务或中断原有会话。其他程序占用端口或旧版服务不兼容时，仍会提示更换端口或关闭旧服务。

1. 注册本地账号，密码至少 8 位。
2. 在“数据与账号”填写 CF handle 和该账号自己的 API Key / Secret，选择“全部历史提交”，点击“获取提交与源码”。凭证在 [CF API 设置](https://codeforces.com/settings/api) 创建，无需提供 CF 登录密码。
3. 在“提交历史”查看各次提交，点击“与上次对比”。或从“题目与代码 → 详情”进入对比。默认比较当前提交与前一次提交；可自行选择同题任意两次提交，或逐组浏览相邻提交。红色表示删除、绿色表示新增，深色块标出行内字符变化。默认显示改动及前后 3 行上下文，可切换完整代码。
4. 设置参考 Rating，进入概率实验室试算未做过的题目。
5. 添加补题或复习任务，置顶、写笔记并标记完成方式。

注册账号、导入数据、源码、偏好和任务保存在 `.local/vplab.sqlite3`，不进入 Git。不同账号的记录互相隔离。重启后需要重新登录，数据仍保留。绑定 handle 不验证归属；一个本地账号暂只对应一个 CF handle。

如果旧版正在运行，先停止旧服务，再重新双击 `StartDemo.cmd`。源码详情也支持新标签页、复制和下载。

## AI 复盘与个人经验库

1. 在“数据与账号 → AI 分析”配置 DeepSeek API Key，也可以在代码旁的分析窗口配置。服务只在内存中保存各账号的密钥；退出登录或重启后重新填写。密钥不保存在浏览器、数据库或导出文件中。
2. 从“提交历史”打开源码，点击“AI 分析”；或在两份代码对比时点击“AI 分析这次修改”。选择“两次提交”或“首次 AC 全过程”。全过程包含最早记录到第一次 AC 的所有判题结果，排除后续 AC；未观察到 AC 时为阶段复盘。
3. 查看预览范围，可以补充题面、问题，选择提示或完整解释模式，并附带最多 3 条已确认经验（选择列表展示最近更新的 20 条）。打开窗口、预览、重读结果均不会调用模型；点击“开始分析”后自动完成两轮：理解题目与代码 → 提炼经验。两轮都会发送选定材料到 DeepSeek，第二轮还包含第一轮草稿；不发送 CF 凭证。
4. 分析按提交逐步说明可观察改动、可能原因与尚未运行的候选验证。点击引用可定位分析时保存的代码快照。服务核对引用的提交、行号与原文；引用核对成功不等于原因已经证明。
5. 将候选“加入待确认”，或在源码旁手动“记录经验”。在“个人经验库”编辑适用场景、规则与检查步骤，再确认入库。支持搜索、状态和来源筛选、收藏、个人练习标记、回收站恢复；同一候选不会重复入库。
6. 在经验来源中点击“回到代码与已保存分析”，读取原始输入快照与结果。后续同步不会覆盖这些快照；快照对比可逐组查看，无需重新调用模型。新分析需要按当前记录重新预览。

模型通过 `ai_provider.py` 接入 [DeepSeek Chat API](https://api-docs.deepseek.com/api/create-chat-completion)，默认 `deepseek-flash`，关闭思考模式；可在启动前用 `VPLAB_AI_MODEL` 修改模型名，地址固定为官方接口。第一轮理解题意、完整代码及实际diff，输出分析草稿（最多3000 tokens）；第二轮基于相同原始材料和草稿，返回现有页面需要的JSON，逐步简述修改并最多提炼一张经验卡（最多6000 tokens）。两轮均不编译或执行源码，不要求人工核验。提示模式在两轮都生效；第一轮草稿只用于后续调用，不展示为已验证结论。

每轮网络读取超时90秒，原始材料最多100000字符 / 20次修改，不静默截断全过程。页面显示两轮进度，成功时合计token用量并保留分轮记录；供应商少报一轮时不显示不完整的总计。任一轮失败都不自动重试、不保存半成品经验。取消会阻止尚未发出的下一轮请求，已发出的请求仍可能计费。输入快照和缓存指纹包含生成配置、两轮流程及提示词哈希，旧结果保留，新请求不复用旧单轮结果。每账号最多一个运行任务，全服务最多两个。不保存或展示模型的原始思考内容。

旧导入文件和旧版同步记录不具有完整历史证明。新版“全部历史提交”成功遍历后才记录覆盖范围；缺少历史或源码时提示片段复盘，需要主动勾选后开始。题面自动获取方式见下文；没有题面时明确限制为代码分析。当前不执行生成用例，不自动确认经验或判定掌握程度，不提供向量检索。源码引用核验失败的候选不能直接入库。

分析快照、结果、经验及修改版本持久化在原 SQLite 数据库，按登录账号隔离；ZIP 导出增加 `analyses.json` 与 `experiences.json`。服务重启会将未完成任务标记为中断，已保存结果和经验仍可查看。运行前建议备份 `.local/vplab.sqlite3`。`design/` 保留早期独立设计稿，实际功能位于主应用的代码查看和经验库页面。

## 原题链接与自动题面

### 浏览器获取（Chrome / Edge）

当直接获取返回 403 时，在源码或对比页点击“浏览器获取题面”。首次需要加载本项目提供的扩展：

1. 在“数据与账号 → 浏览器题面助手”打开安装说明并下载 ZIP、解压；也可直接使用项目内 `browser_helper` 文件夹。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`，开启开发者模式，选择“加载已解压的扩展程序”，选中含 `manifest.json` 的文件夹。
3. 在同一浏览器刷新 VP Lab，检查连接，然后点击代码旁的“浏览器获取题面”。
4. 助手打开指定 CF 原题。若出现验证，请手动完成；题面出现后自动回传。CF 页面显示成功提示，VP Lab 自动更新题面与尚未开始的分析预览。

扩展不要求 CF 密码、Cookie 或源码权限，不自动提交代码；只处理由 VP Lab 主动创建、绑定到特定标签页的题面任务。短期回传令牌保存在扩展会话存储，十分钟到期，任务结果和页面不显示令牌；退出本地账号后撤销任务。服务重启后需重新登录并重新发起。关闭原题标签页会将未完成任务标为失败。Chrome/Edge 如果提示本地网络访问，请允许助手连接正在运行的本地 VP Lab。

MathJax 的原始 TeX 优先提取并去除重复渲染，样例按行保留；找不到公式原文时注明限制。图片仍仅提示，不进行图像识别。浏览器题面缓存按本地账号隔离，不进入其他用户的缓存，AI 快照来源标为 `codeforces_browser`。扩展仅支持 `codeforces.com` 的 contest/gym 题页；其他域名、PDF 题面以及其他 OJ 尚未接入。

下载包由 `GET /browser-helper.zip` 从扩展源文件生成。安装后需要保留文件夹；代码更新后在扩展管理页面点击重新加载，并刷新 VP Lab。扩展与后台的逻辑、权限边界和 HTTP 回传已有自动化测试；当前环境没有可用的浏览器控制通道，真实扩展安装、CF 验证和采集成功流程仍需在浏览器验收。

### 直接获取与缓存

题面显示使用本地 KaTeX 0.19.1，将已有文本中的 CF `$$$…$$$` 公式渲染为数学排版，同时整理标题、限制、章节与样例。已有缓存和分析快照可直接使用，无需重新采集。样例保持纯文本和换行；不支持的公式保留原文并提示。只转义展示原文，不注入采集页面的 HTML，KaTeX 禁用可信命令并限制宏展开。库、样式和字体位于 `static/vendor/katex/`，附 MIT 许可证与来源/完整性元数据；不会向外站发送题面。

源码查看、代码对比和 AI 侧栏均提供原题链接。打开当前记录的源码或对比页时，自动读取 CF 公开题面；代码立即显示，不等待题面。提取题意、约束、输入输出、样例和备注，保留 LaTeX 原文与样例换行。展示纯文本，不执行原站 HTML；题面包含图片时明确提示，当前不下载图片或进行视觉识别。

公开题面按平台和题号缓存在 SQLite；成功缓存默认使用 7 天，可主动刷新，同题刷新至少间隔 60 秒。失败缓存 60 秒，全局串行访问且间隔至少 2.1 秒，网络超时 18 秒；刷新失败保留已有文字。接口只允许获取当前用户已有记录的题目，URL 由适配器生成，不接受任意网址，不携带 CF 凭证。后续平台可实现 `PlatformAdapter.fetch_statement(record)`。

AI 预览和创建默认使用缓存题面，将来源、原题链接、获取时间和正文保存到不可变分析快照。手动填写题面时明确记为用户补充，优先于自动结果；刷新造成输入变化时需重新预览。CF 返回 403、429、验证页面或登录页时显示失败原因，不冒充获取成功；可以打开原题、稍后重试或手动补充。当前本机对 CF 1900A 的真实网络验证返回 HTTP 403，成功解析路径通过模拟页面测试，尚未在本机验证线上成功抓取。

## 在线源码同步

使用 [CF 官方 API](https://codeforces.com/apiHelp/methods) 的签名 `user.status(includeSources=true)`，每页 200 条，所有请求共用至少 2.1 秒的调用间隔。源码权限由 CF 决定，只支持 API 凭证所属账号的源码；本平台不验证绑定归属，不代表能够用任意人的 Key 读取其他账号源码。

Key / Secret 只进入当前 HTTP 请求和同步线程内存，不写数据库、日志、浏览器存储或任务状态。页面提交后清空输入框。每次同步需要重新输入；任务结束释放引用，但不承诺进程内存的物理擦除。

页面展示进度并允许中止。每页事务写入，失败、中止、服务重启都保留已完成的分页；当前网络调用结束后执行中止。进程重启后同步任务不能继续，需要重新发起，已有提交按编号去重。最多遍历 100000 条；超过上限会明确标记未完成。CF 分页不是快照，同步期间有新提交时建议再同步一次。未返回源码的记录会标注，并且不会清除已有源码。

旧 JSONL 导入保留在折叠的备用入口。原 `E:/codeforces_submissions.jsonl` 只有 AC 样本，无法显示此前 WA 到 AC 的改动链。代码对比仅展示文本差异，不把某次修改自动解释为错误原因；单份代码最多 200000 字符 / 5000 行。

## 已实现与限制

- 注册、登录、退出；密码使用 PBKDF2 加盐哈希；会话放在内存，Cookie 为 HttpOnly / SameSite。
- CF JSONL 和原始提交 JSON 数组导入；支持 `source` / `sourceBase64`。先验证整份文件再事务写入。重复导入按提交编号更新。
- CF 公开资料及最近最多 1000 次提交同步；网络失败不会清除已有记录。此入口不获取源码，不表示完整历史。
- 官方签名源码同步、完整历史分页、进度与中止；支持记录查询、单次源码读取及同题两次提交对比。
- 题目去重、标签及难度分布、标签 × 难度矩阵、UTC 月份提交统计；不把只含 AC 的文件当作完整通过率数据。
- 私有源码查看、复制、保存；ZIP 导出规范化记录及源码。ZIP 内 `records.normalized.json` 是内部规范格式，目前不是文件导入器的输入格式。
- 概率仅为 `sigmoid((referenceRating - problemRating - 100) / 300)` 规则演示，固定两小时 VP 假设，参数人为指定。未经训练和校准，标签及源码不参与计算，无性能承诺。已通过题返回“不适用”，缺少难度或参考 Rating 时不返回概率。
- 补题排序为人工规则；完成状态由用户确认，不能据此伪造 AC 记录。复习任务与首次解题记录分开。
- 团队分支已实现 1～3 人房间和基于时长、当前全部成员已知接触记录的历史赛筛选；经训练的概率模型、跨 OJ 适配不在本次交付中。
- 本版仅绑定回环地址，用于本地课程 Demo；尚未具备公网部署所需的登录限流、账号找回、HTTPS 和生产监控。

## 模块与接口

- `adapters.py`：平台协议、能力声明、CF 数据规范化及同步。
- `domain.py`：纯统计、概率估算、补题排序，可独立替换模型。
- `server.py`：HTTP 接口、账号会话、SQLite 持久化、按用户授权。
- `review_service.py`：分析范围、快照、任务与证据验证、经验库和版本控制。
- `ai_provider.py`：模型供应商边界，结构化请求和错误处理，不执行源码。
- `prompts/review-analyze.txt`、`prompts/review-distill.txt`：正式采用的纯AI两轮提示词；输入/JSON字段适配在provider中维护。
- `problem_statement.py`：题面 HTML 提取、固定原站地址、缓存与限流。
- `browser_bridge.py`：按账号和题目绑定的短期浏览器采集任务与回传校验。
- `browser_helper/`：Chrome / Edge Manifest V3 扩展源码，无第三方运行依赖。
- `static/`：无构建依赖的响应式前端。

业务接口：`/api/dashboard`、`/api/problem`、`/api/import`、`/api/sync`、`/api/predict`、`/api/tasks/create`、`/api/tasks/update`、`/api/settings`、`/api/export`。

### 日常训练：日常练习与专项训练

左侧「日常训练」可切换日常练习和专项训练，每次推荐一道 CF 题目，不显示题目标签。默认参考水平取当前 CF Rating，无评级则用 1800；轻松、正常、挑战三个默认区间均跨度 400，也可手动设置固定上下限。按长期覆盖与最近 10 道训练题的标签权重先选方向、再选题；具体规则和接口见 [日常练习设计](design/daily-training.md)。

点击「开始训练」才建立记录；换题或跳过原因可不填，当天冷却，已开始的题保留在「尝试过的题目」。只有同步到开始后的 CF AC 才能进入必填反馈（独立 / 提示 / 题解），反馈完成后推荐下一题。每 3 道有效反馈评估一次训练参考水平；官方 Rating 变化时覆盖并重置评估窗口。页面每分钟尝试同步有未完成记录的账号，也可手动同步；最近 1000 次提交之外的记录需要通过已有历史同步入口补齐。

`training_service.py` 负责持久化状态、过滤、权重选题和参考水平，`static/training.js` / `training.css` 为独立页面模块。通过适配器获取题库，缓存 24 小时；题库 API 当前使用 CF 官方 `problemset.problems`。只推荐有难度的题，不声称覆盖全部 Gym。无候选时不自动放宽条件。专项训练现已开放：选择 1～3 个方向，先等概率选可用方向，再随机选题。两种模式独立保存设置与 Rating，分别累计三题反馈；官方 Rating 变化时同时覆盖。共用一道进行中的题、尝试记录、AC 和当天冷却，切换不会跳过当前题。反馈按训练首次所属模式计入，不会因为切换页面而调错 Rating。智能推荐保持独立入口；VP 见训练房说明。

新增接口均要求登录：GET `/api/training`、GET/POST `/api/training/preferences`、POST `/api/recommendations`、POST `/api/training/start,dismiss,skip,resume,feedback,refresh`（分别为六个路径）。写接口沿用现有 POST 约定，状态响应不包含标签。运行 `python -m unittest discover -s tests -p test_training.py -v` 验证训练规则；接口鉴权和状态流转纳入 `test_demo.py`，前端模板和异步隔离纳入 `test_ui.cjs`。

新增接口（均要求登录，并按当前用户隔离）：

| 方法 / 路径 | 用途 |
| --- | --- |
| POST `/api/sync/source` | JSON：`handle, apiKey, apiSecret, mode`；mode 为 `all` 或 `recent`，返回 202 和任务状态 |
| GET `/api/sync/source/status` | 当前账号的任务进度，不包含凭证 |
| POST `/api/sync/source/cancel` | 中止当前账号的同步任务 |
| GET `/api/submissions?q=&verdict=&source=&page=` | 每页 25 条历史记录；source 为 yes/no/空，列表不返回代码正文 |
| GET `/api/submission?id=&platform=codeforces` | 读取一次提交及源码 |

| POST `/api/browser/result` | 扩展通过 `X-VPLab-Token` 回传指定任务的题面 HTML；验证题目网址、大小、有效题面和任务状态后保存 |

## 验证

### AI 复盘与两轮调用（review-4-two-stage）

以下四例来自本地已有分析，用于人工对照新旧输出；不将用户源码或分析正文加入仓库。

| 题号 / 任务 | 验收重点 |
| --- | --- |
| 2207E2：单份 AC | 使用已提供题面解释关键思路；不虚构失败过程，不将“未执行测试”说成“无题面” |
| 104270C：公式修改，WA→AC | 推导旧公式与新公式的行为差异，给合法小例子；经验聚焦实际改动 |
| 2216D：实现修改，TLE→AC | 检查调用路径，区分复杂度与常数；不把未调用函数的删除当成运行加速 |
| 1641D：多次 TLE/WA→AC | 区分 9 份源码与 8 次转换，梳理性能到正确性的演进；不凭 AC 断言哈希碰撞 |

共同要求：结合题目目标、关键约束与完整代码，解释“题目性质 → 代码行为 → 改动影响”。第一轮理解，第二轮整理简短步骤与最多一张经验卡；第二轮仍需阅读原始材料，不把第一轮草稿当标准答案。不强行编造反例，无必要自检建议时可以留空。公共限制集中说明，源码引用须通过行号与内容校验（仅核对引用，不证明推理正确）。新prompt版本与内容哈希参与分析指纹，旧分析保留，新请求不会复用旧版本结果。重启服务后生效。

`test_ai_workflow.py` 用模拟供应商响应验证两轮材料传递、实际diff、JSON适配、用量合计、缺失用量、取消后不发第二轮、失败不重试以及单份/两份/多份源码。它不评估模型能力。实验脚本、模型原文和报告保存在已忽略的`.local/`；未采用的`design/prompts/`及实验结论文件也由`.gitignore`排除，正式提示词与产品测试保留在版本管理中。

`test_review_inputs.py` 检查四类输入、题面与记录数量事实，以及 CRLF/LF 引用兼容性；错误代码、缩进和行号仍会被拒绝。这些是输入及校验器测试，真实模型的新输出仍需按上述标准逐例评阅。

运行 `python -m unittest discover -s tests -v` 和 `node tests/test_ui.cjs`。测试使用临时数据库，不会修改实际用户记录。在线 API 使用模拟响应验证签名、分页、失败保留和中止，不表示已经用真实凭证完成线上验证。AI 测试模拟供应商响应，覆盖首次 AC 截止、缺失源码、任务取消、结果复用、证据拒绝、快照不可变、账号隔离、经验确认和版本冲突；不代表真实模型分析质量已验收。前端测试检查模板与异步交互逻辑，不替代浏览器视觉验收。

运行 `node tests/test_helper.cjs` 验证扩展的标签页任务绑定、回传地址、令牌隔离、关闭清理，以及公式/样例提取逻辑。这里使用 Chrome API 与 DOM 模拟对象，不会驱动真实浏览器。
